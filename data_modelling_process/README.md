# Data Modelling Process — Senior Data Modeller Kickstart Guide

This folder contains a complete, practical playbook for a **Senior/Lead Data Modeller** starting at a new company. It covers the first 90 days with concrete deliverables, templates, checklists, and workshop guides.

## Contents

| File | Purpose |
|------|---------|
| `SENIOR_DATA_MODELLER_KICKSTART_GUIDE.md` | Main 90-day playbook (Phases 0–4, deliverables, behavioural anchors) |
| `templates/MODELLING_STANDARDS.md` | Living modelling standards template (ratify with your team) |
| `templates/MODEL_REVIEW_CHECKLIST.md` | PR / design review checklist (structural, business, technical, governance) |
| `templates/ARCHITECTURE_DECISION_RECORD.md` | ADR template for modelling decisions |
| `templates/SOURCE_TO_TARGET_MAPPING.md` | Source-to-target mapping template |
| `templates/ENTITY_CATALOGUE_ENTRY.md` | Minimal entity catalogue entry (YAML front-matter + markdown) |
| `checklists/WEEK_1_DISCOVERY_CHECKLIST.md` | Day-by-day Week 1 orientation checklist |
| `checklists/QUICK_WIN_VALIDATION.md` | Criteria to ship a quick win confidently |
| `checklists/MODEL_COMPLETENESS_DEFINITION_OF_DONE.md` | Definition of Done for any data model |
| `checklists/ANTI_PATTERN_DETECTION.md` | Common anti-patterns to hunt during reviews |
| `workshops/CONCEPTUAL_MODELING_WORKSHOP.md` | 90-min cross-functional workshop facilitation guide |
| `workshops/STAKEHOLDER_INTERVIEW_QUESTIONS.md` | Structured interview questions by role |

## Quick Start

1. Read `SENIOR_DATA_MODELLER_KICKSTART_GUIDE.md` end-to-end
2. Clone the templates into your team's wiki/Notion/Confluence
3. Run the Week 1 Discovery Checklist on your first day
4. Book the Conceptual Modelling Workshop by end of Week 2
5. Ratify `MODELLING_STANDARDS.md` by end of Week 4

## Philosophy

> **Business meaning before implementation. Grain before structure. Keys before relationships. Explicit over implicit. History is a requirement. Governance by design. Data quality by design. Technology-aware but technology-independent. Simplicity. Traceability.**

*(From the SOUL.md that defines the Hermes Data Architect persona)*
